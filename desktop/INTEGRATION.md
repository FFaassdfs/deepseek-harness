# 桌面版与 Harness 本体的集成方案

本文档梳理 dsh-desktop（桌面壳）与 DeepSeek Harness 本体如何更好地配合，作为后续迭代的路线图。

## 进度

- ✅ 启动命令与端口可配置（`config.json`：`port` / `command` / `autoUpdateHarness`）
- ✅ 崩溃自愈（运行中检测掉线，自动重启自拉起的实例并重连）
- ✅ 错误诊断（启动/崩溃失败时展示 `dsh.log` 尾部）
- ⏳ 自动更新 harness（`autoUpdateHarness`，待确认是否保留）
- 其余（优雅关闭、启动模式感知、通知、托盘、深链、设置透传、版本协调、会话入口）待做

## 现状

桌面壳目前是一个「哑壳」：硬编码拉起 `dsh web`，轮询 `127.0.0.1:3080` 就绪后跳转。它不了解 harness 的配置、端口、会话、凭据与生命周期，二者仅通过「端口 3080 + WebView2」这一个薄接口相连。

## 集成原则

- **harness 是大脑，桌面壳是薄原生层**：业务逻辑全部留在 harness；桌面壳只补 Web 环境缺失的原生能力（进程编排、托盘、通知、深链、文件关联、系统集成）。
- **单一配置来源**：端口 / 启动命令 / 模式等以 harness 为权威，桌面壳读取并跟随，避免两处硬编码失配。
- **生命周期自洽**：桌面壳拉起、守护、优雅回收 harness 进程，且能应对 harness 崩溃。

## 改进方向（按优先级）

### P0 —— 配置与生命周期对齐

1. **启动命令与端口可配置**：把 `dsh web` 与 `127.0.0.1:3080` 从硬编码改为可配置（`desktop/config.json` 或环境变量），默认与 harness 默认一致；支持自定义 `--port` / profile。
2. **就绪握手更稳**：不只靠轮询 HTTP 200，可让 harness 侧写就绪标记（ready file / 状态端点），桌面壳据此跳转。
3. **优雅关闭**：退出时先请求 harness 自行退出（信号 / HTTP 端点），超时才 `taskkill`；避免强杀导致 SQLite 会话未落盘。
4. **崩溃自愈**：运行中检测 3080 掉线，自动重启并重新跳转（或给出可重试提示）。

### P1 —— 启动模式与原生能力

5. **启动模式感知**：自动区分「源码模式」（仓库根 `pnpm dsh web`）与「npm 模式」（全局 `dsh web`），提供 `--mode dev|prod`。
6. **系统通知**：订阅 harness 事件流（WebSocket `/api/events.*`）或轮询状态端点，长任务完成 / 报错时发原生通知。
7. **托盘常驻**：托盘图标显示运行状态，提供「显示窗口 / 打开日志 / 退出」等快捷操作。
8. **深链与文件关联**：注册 `dsh://` 协议，外部链接直接唤起并路由到指定会话。

### P2 —— 配置共享与体验

9. **设置 / 凭据透传**：桌面壳读取并透传 `DEEPSEEK_API_KEY`、`.env`；可选提供原生「设置」入口读写 harness settings。
10. **版本协调**：`dsh --version` 与桌面壳记录的兼容版本比对，提示升级。
11. **会话入口**：原生「最近会话」列表、开机自启、多窗口。

## 下一步建议

先落地 P0.3 优雅关闭与 P1 原生能力（通知 / 托盘），它们是剩余的高价值项。
